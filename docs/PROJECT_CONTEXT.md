# Project Context

## Product goal

Build an AI-assisted Facebook/Messenger sales bot for TRANSO. It should identify customer intent and product details, query real product/price/inventory data, draft a response, and hand control to an employee when required.

## MVP boundary

The first MVP is employee-assisted, not fully autonomous.

Included:

- Receive and persist Messenger webhook events.
- Store conversations and messages.
- Classify a small set of intents.
- Search products through an `InventoryProvider`.
- Retrieve real price and inventory.
- Draft an employee-reviewable response.
- Record integration errors and support human handoff.

Excluded:

- Multi-tenant SaaS.
- Microservices, Kubernetes, Kafka, or complex multi-agent systems.
- Full CRM replacement.
- Autonomous official order creation.
- Autonomous refund decisions.
- Employee webcam or continuous screen monitoring.

## Confirmed architecture

- Modular monolith.
- One backend and one primary PostgreSQL database.
- Java 21, Spring Boot, Maven Wrapper, Flyway, Docker Compose.
- React/Vite/TypeScript dashboard only when the backend workflow requires it.

## Decision principles

- Rules first, deterministic search second, LLM only when needed.
- Backend owns business decisions.
- LLM output must be structured and validated.
- Real price and inventory are never generated by an LLM.
- Human handoff is a product requirement, not an error case.
- Integrations need logging, retry controls, deduplication, and idempotency.
- The system must not be tightly coupled to one CRM vendor.
